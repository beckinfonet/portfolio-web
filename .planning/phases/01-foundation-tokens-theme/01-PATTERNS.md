## Greenfield Posture

At phase start the repository tree contains only `.git/`, `.planning/`, and `CLAUDE.md`. There is **no `package.json`, no `src/`, no `app/`, no `node_modules`, no existing source file of any kind**. Every file Phase 1 creates is load-bearing for later phases and has **no in-repo analog**.

**Consequence for this pattern map:** the "Closest Analog" column is **`none (greenfield)`** for every row. Instead of citing in-repo files, each row cites the authoritative external reference — `STACK.md` § + version pin, `ARCHITECTURE.md` rule, `PITFALLS.md` anti-pattern, or the official-docs excerpt reproduced in `01-RESEARCH.md`/`01-UI-SPEC.md`. The planner and executor MUST lean on those canonical references rather than inventing patterns.

**Consequence for later phases:** every file listed below becomes the analog for Phase 2+. After Phase 1 lands, `src/app/layout.tsx` is the analog for any new layout, `src/components/theme-toggle.tsx` is the analog for new client-leaf components, `src/app/globals.css` is the analog for any token additions, `.github/workflows/ci.yml` is the analog for any new CI step, and `tests/tokens.contrast.test.ts` is the analog for new token-layer validation tests.

**Do NOT fabricate analogs.** If a pattern isn't in `.planning/research/` or in the phase's `01-RESEARCH.md`/`01-UI-SPEC.md`, it doesn't exist yet — flag it as a discretion call for the planner.

## File Classification

Every file is new. Roles are grouped into seven classes so the planner can wave them:

| Role class | Meaning |
|---|---|
| `config` | Non-TS/TSX configuration consumed by tooling (tsconfig, biome.json, postcss, vitest, next.config). No runtime code. |

| `runtime-server` | Server-only React — RSC (`src/app/layout.tsx`, `src/app/page.tsx`). Zero `"use client"`. |

| `content` | Human-authored prose files (README.md). No JSX copy allowed per CLAUDE.md. |

### 12. `src/components/theme-toggle.tsx` (runtime-client — **the only true leaf**)

- **Analog:** none (greenfield). **Flagged per CLAUDE.md:** this is the ONLY `"use client"` true-leaf component in Phase 1. Page-level `"use client"` is forbidden.
- **Authoritative reference:** RESEARCH Pattern 2 `theme-toggle.tsx` snippet + UI-SPEC §"ThemeToggle affordance" table (binding).
- **Binding contract** (UI-SPEC §"ThemeToggle affordance"):

  | Property | Value | Why |
  |---|---|---|
  | Element | `<button type="button">` (NEVER `<div>`/`<span>` with `onClick`) | Keyboard + SR accessibility (PITFALLS.md §13) |
  | Size | `h-11 w-11` minimum (44×44 CSS px) | A11Y-06 touch target |
  | Icon (Phase 1) | Raw Unicode `☀` (dark → light) / `☾` (light → dark) | `lucide-react` not installed in Phase 1; Phase 3 swaps |
  | `aria-label` | Dynamic: `` `Switch to ${next} theme` `` where `next = resolvedTheme === "dark" ? "light" : "dark"` | Never "Open/Close menu" (SR noise; RESEARCH §Pitfall 5) |
  | Keyboard | Default `<button>` Enter + Space; **do NOT override** | WCAG 2.1.1 |
  | Focus ring | Inherits global `:focus-visible` (2px accent outline + 2px offset) | UI-SPEC §Focus contract |
  | Mounted guard | `useState(false)` + `useEffect(() => setMounted(true), [])`; unmounted = layout-preserving placeholder `<button disabled aria-label="Toggle theme" className="h-11 w-11" />` | RESEARCH §Pitfall 5 (hydration mismatch) |
  | Background/border idle | None — transparent | UI-SPEC minimal-aesthetic rule |
  | Hover | **None in Phase 1** | UI-SPEC §Motion Contract (no motion) |

- **Related pitfalls:**
  - §Pitfall 5 — hydration mismatch. The snippet's `mounted` state with the disabled placeholder is the mitigation. Do not short-circuit.
  - §Pitfall 4 — `disableTransitionOnChange` on the provider (not the toggle) prevents flicker.

### 13. `tests/tokens.contrast.test.ts` (CI / validation)

- **Analog:** none (greenfield). Becomes the analog for any future token-layer validation test.
- **Authoritative reference:** RESEARCH Pattern 4 (full test file reproduced) + UI-SPEC §"Contrast gate" (the six assertions spelled out).
- **Six assertions (non-negotiable, UI-SPEC §"Contrast gate"):**
  ```
  light: text-primary (#0a0a0a) vs bg (#ffffff) ≥ 7
  light: text-secondary (#525252) vs bg (#ffffff) ≥ 4.5
  light: accent (#0057ff) vs bg (#ffffff) ≥ 3
  dark:  text-primary (#fafafa) vs bg (#0a0a0a) ≥ 7
  dark:  text-secondary (#a3a3a3) vs bg (#0a0a0a) ≥ 4.5
  dark:  accent (#4d8bff) vs bg (#0a0a0a) ≥ 3
  ```
- **Loop shape (RESEARCH Pattern 4):** `for (const mode of ["light", "dark"] as const)` — one describe, six asserts via three `test()` calls × two modes.
- **Binding constraint:** if any ratio fails, **update hex values, never weaken the threshold** (UI-SPEC §"Contrast gate").
