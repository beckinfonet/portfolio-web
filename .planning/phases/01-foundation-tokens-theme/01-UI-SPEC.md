# Phase 1 — UI Design Contract: Foundation, Tokens, Theme

> Token contract + minimal proof-of-life page contract for the Next.js 16 scaffold, Tailwind v4 `@theme` block, Geist fonts, and FOUC-free `next-themes` dark mode. Downstream phases (Shell, Hero, Sections, Projects) consume these tokens verbatim — every value committed here is load-bearing and not re-litigable in Phase 3+.
>
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope & Intent

Phase 1 ships **machinery, not components**:

1. The Tailwind v4 `@theme` token block (colors × 2 themes, fonts, type scale, weights, spacing, radii, borders, focus ring).
2. FOUC-free theme machinery (`next-themes` wired at root, blocking inline script, `suppressHydrationWarning` on `<html>`).
3. One proof-of-life `app/page.tsx` — a single `<main>` with a placeholder headline, subhead, and a `ThemeToggle` — enough to prove Geist loads and dark mode flips with no flash.

This contract fixes the **visual primitives** every later phase inherits. It does **not** design the header, nav, hero, project cards, case-study layouts, or footer — those are Phases 3–5 and will have their own UI-SPECs that consume the tokens declared here.

## Color Contract

### 60 / 30 / 10 Split

The portfolio is aggressively monochrome. The traditional "60/30/10" breakdown maps to:

- **60% — Dominant surface:** `--color-background` (the page canvas — `#ffffff` light / `#0a0a0a` dark).
- **30% — Secondary surface:** `--color-surface` (raised surfaces: cards in Phase 5, section-level contrast blocks — **unused in Phase 1's proof-of-life page; declared now for downstream consumers**).
- **10% — Accent:** `--color-accent` — a single neutral blue hue. **Reserved-for list** (binding for Phases 3–5):
  - Focus-visible outline on interactive elements (`ring` color)
  - Primary CTA background (Phase 4 hero)
  - Active state on nav links (Phase 3)
  - Links inside prose body (Phase 5 case studies)
  - **Not used for:** decorative accents, headings, borders, dividers, icon fills, progress indicators, skill tags. Those stay monochrome.

**Second semantic color:** none in Phase 1 or v1. No destructive actions exist on a portfolio — there is nothing to delete or confirm. `--color-destructive` is explicitly **not** declared.

### Light-theme token values

| Token | Hex | Role | Contrast vs `--color-background` (`#ffffff`) | Threshold |
|-------|-----|------|----------------------------------------------|-----------|
| `--color-background` | `#ffffff` | Page canvas | — | — |
| `--color-surface` | `#f7f7f7` | Raised surfaces (deferred use) | 1.05:1 vs bg | not a text pair |
| `--color-border` | `#e5e5e5` | Hairlines, dividers | 1.25:1 vs bg | not a text pair |
| `--color-text-primary` | `#0a0a0a` | Body text, headings | **≈ 20.4:1 (AAA ✓)** | ≥ 7:1 |
| `--color-text-secondary` | `#525252` | Meta, captions, muted prose | **≈ 7.6:1 (AA ✓, AAA borderline)** | ≥ 4.5:1 |
| `--color-accent` | `#0057ff` | Focus ring, primary CTA, link | **≈ 5.6:1 (AA ✓ for interactive)** | ≥ 3:1 |

### Dark-theme token values

| Token | Hex | Role | Contrast vs `--color-background` (`#0a0a0a`) | Threshold |
|-------|-----|------|----------------------------------------------|-----------|
| `--color-background` | `#0a0a0a` | Page canvas (**NOT** pure `#000` — PITFALLS.md §4) | — | — |
| `--color-surface` | `#161616` | Raised surfaces | 1.32:1 vs bg | not a text pair |
| `--color-border` | `#262626` | Hairlines, dividers | 1.80:1 vs bg | not a text pair |
| `--color-text-primary` | `#fafafa` | Body text, headings | **≈ 18.6:1 (AAA ✓)** | ≥ 7:1 |
| `--color-text-secondary` | `#a3a3a3` | Meta, captions, muted prose | **≈ 8.3:1 (AA ✓, AAA ✓)** | ≥ 4.5:1 |
| `--color-accent` | `#4d8bff` | Focus ring, primary CTA, link (desaturated for dark) | **≈ 5.4:1 (AA ✓ for interactive)** | ≥ 3:1 |

All six text/interactive pairings pre-verified against WCAG 2.1 AA + AAA thresholds. The Vitest `tests/tokens.contrast.test.ts` gate (required by A11Y-03, D-06, D-07) asserts these six ratios in CI.

### Naming rationale

Token names use the `--color-*` namespace so Tailwind v4 auto-generates utilities (`bg-background`, `text-text-primary`, `border-border`, `ring-accent`, etc.). **Do not rename to shorter forms** (`--color-bg`, `--color-text`) — the longer names read better in generated utility class names and match the RESEARCH §Common Pitfall 3 guidance.

### Contrast gate

The CI workflow runs `tests/tokens.contrast.test.ts` (Vitest + `wcag-contrast`), which asserts **six** ratios:

```
light: text-primary (#0a0a0a) vs bg (#ffffff) ≥ 7     → AAA body
light: text-secondary (#525252) vs bg (#ffffff) ≥ 4.5 → AA meta
light: accent (#0057ff) vs bg (#ffffff) ≥ 3           → AA interactive
dark:  text-primary (#fafafa) vs bg (#0a0a0a) ≥ 7     → AAA body
dark:  text-secondary (#a3a3a3) vs bg (#0a0a0a) ≥ 4.5 → AA meta
dark:  accent (#4d8bff) vs bg (#0a0a0a) ≥ 3           → AA interactive
```

A regression in any value fails CI. **Do not weaken the thresholds** to pass — update the hex values.

## Typography Contract

### Font families

| Variable | Value | Applied via | Usage Scope |
|----------|-------|-------------|-------------|
| `--font-sans` → aliased to `--font-geist-sans` | Geist Sans (variable font) | `<html className={GeistSans.variable}>`; Tailwind `font-sans` | **All prose, headings, UI labels.** Default. |
| `--font-mono` → aliased to `--font-geist-mono` | Geist Mono | `<html className={GeistMono.variable}>`; Tailwind `font-mono` | Code blocks, skill tags, `<kbd>` shortcuts, meta accents (dates, timestamps, numerics, role/scope labels). **Never prose or headings** (CONTEXT D-02). |

Italic variant: sans italic shipped via Geist variable font's built-in support. Mono italic: **not tokenized** in Phase 1 (CONTEXT D-01 discretion).

### Type scale (major-third ratio, 1.25, base = 1rem = 16px)

| Token | rem | px | Applied to | Line height | Weight default |
|-------|-----|----|----|-------------|----------------|
| `--text-caption` | 0.8125rem | 13px | Captions, footnotes, fine-print meta | 1.5 | 400 |
| `--text-body` | 1rem | 16px | Body prose, default UI text | 1.5 | 400 |
| `--text-lg` | 1.25rem | 20px | Subhead, lead paragraph, h4-equivalent | 1.4 | 500 |
| `--text-h4` | 1.5625rem | 25px | h4 | 1.3 | 700 |
| `--text-h3` | 1.953125rem | 31px | h3 | 1.25 | 700 |
| `--text-h2` | 2.44140625rem | 39px | h2 | 1.2 | 700 |
| `--text-h1` | 3.0517578125rem | 49px | h1 (page titles, project detail title) | 1.15 | 700 |
| `--text-display` | 3.814697265625rem | 61px | Hero name (Phase 4), single largest text on the site | 1.1 | 800 |
| `--text-mono-sm` | 0.875rem | 14px | Inline mono (tags, dates, kbd) | 1.5 | 400 |
| `--text-mono-base` | 1rem | 16px | Code block body | 1.55 | 400 |

**Scale math:** Each sans step = `16px × 1.25^n`. Numbers look ugly in `rem` because `1.25` doesn't produce round values — that's expected and fine. Tailwind v4 generates the utility classes (`text-display`, `text-h1`, etc.) directly from the `--text-*` tokens.

**Ratio rationale:** Major-third (1.25) was chosen over minor-third (1.2, too cramped — headings blur together) and perfect-fourth (1.333, too theatrical for a minimal portfolio). RESEARCH §Open Question 3 backs this choice.

### Weight tokens

| Token | Value | Usage |
|-------|-------|-------|
| `--font-weight-regular` | 400 | Body prose, UI default |
| `--font-weight-medium` | 500 | Labels, subheads, lead paragraphs, interactive UI |
| `--font-weight-bold` | 700 | h1–h4 headings |
| `--font-weight-extrabold` | 800 | Display heading only (hero name in Phase 4) — **use Tailwind v4's built-in `font-extrabold` utility; do not manually declare the token** |

Total tokenized weights: **3 explicit (400/500/700) + 1 inherited from Tailwind defaults (800)**. Geist is a variable font so intermediate weights cost zero bytes.

### Line-height defaults

- **Body prose / UI:** 1.5 (`leading-relaxed`-equivalent).
- **Headings h1–h4:** 1.15–1.3, tightening as size grows (see table above).
- **Display:** 1.1.
- **Mono:** 1.5 for inline, 1.55 for code blocks (slightly looser for scannability).

### Letter-spacing

- **Display + h1:** `tracking-tight` (`-0.02em`) — headings need slight negative tracking to avoid feeling airy at large sizes.
- **h2–h4, body, mono:** default `tracking-normal` (0).
- **Uppercase labels:** reserved for Phase 3+; not used in Phase 1 proof-of-life.

## Spacing Scale

**Base: 4px.** All spacing must be a multiple of 4.

| Token | Value | px | Usage |
|-------|-------|----|----|
| `--spacing-0` | 0 | 0 | Zero gap |
| `--spacing-1` | 0.25rem | 4 | Icon-to-label gaps, hairline padding |
| `--spacing-2` | 0.5rem | 8 | Compact inline spacing, tag padding |
| `--spacing-3` | 0.75rem | 12 | Button padding-y, small gaps |
| `--spacing-4` | 1rem | 16 | **Default element spacing**, paragraph gaps |
| `--spacing-6` | 1.5rem | 24 | Card padding, form control spacing |
| `--spacing-8` | 2rem | 32 | Section-internal gaps, nav height |
| `--spacing-12` | 3rem | 48 | Section gutters on mobile |
| `--spacing-16` | 4rem | 64 | Section gutters on desktop, hero vertical padding |
| `--spacing-24` | 6rem | 96 | Major section breaks (hero → projects) |
| `--spacing-32` | 8rem | 128 | Page-level vertical rhythm (rarely used) |

**Usage discipline (binding for downstream phases):**

- **Component padding:** `--spacing-3` to `--spacing-6` (button, input, card internal).
- **Section padding:** `--spacing-16` vertical, `--spacing-6` horizontal gutter on mobile / `--spacing-16` on desktop.
- **Section gap (vertical rhythm between home-page sections):** `--spacing-24` mobile / `--spacing-32` desktop.
- **Page gutter (outer margin):** `--spacing-6` mobile (24px) / `--spacing-16` desktop (64px).

**Tailwind v4 note:** Tailwind's built-in `--spacing` token generates the full `0 / 0.5 / 1 / 1.5 / 2 / ...` scale automatically. We do **not** redeclare `--spacing-*` in `@theme` — we rely on Tailwind's defaults. The table above documents what the team uses from that default scale, not a custom override.

**Exception:** Touch targets (buttons, icon buttons including ThemeToggle) must be **≥ 44 × 44 CSS pixels** (A11Y-06). For the ThemeToggle this means the clickable area is padded to at least `h-11 w-11` (44px), even if the visual icon is smaller. This is a minimum, not a token — enforced component-by-component.

## Radii, Borders, Focus Ring

### Radii

| Token | Value | px | Usage |
|-------|-------|----|----|
| `--radius-sm` | 0.125rem | 2 | Tags, mono labels, fine-detail UI |
| `--radius-md` | 0.25rem | 4 | Buttons, inputs, cards |
| `--radius-lg` | 0.5rem | 8 | Modal/dialog panels (Phase 3+), image containers |

**Banned:** pill shapes (`rounded-full` on containers), large radii (`> 8px`), mismatched radii across related elements. The minimal aesthetic is **subtle corners, not rounded cards**. CLAUDE.md "minimal / typography-forward".

### Borders

| Token | Value | Usage |
|-------|-------|-------|
| `--border-width-default` | 1px | All borders, all dividers. |
| `--border-color-default` | `var(--color-border)` | Hairlines in both themes (light `#e5e5e5` / dark `#262626`) |

**Banned:** borders thicker than 1px; multi-color decorative borders.

### Focus-visible ring

**Contract (WCAG 2.4.7 compliant, keyboard-only not mouse):**

| Property | Value |
|----------|-------|
| Selector | `:focus-visible` (NOT `:focus` — avoids mouse-click focus rings, which look broken) |
| Style | `outline: 2px solid var(--color-accent); outline-offset: 2px;` |
| Light-theme color | `#0057ff` on `#ffffff` → 5.6:1 (passes ≥ 3:1 adjacent-contrast) |
| Dark-theme color | `#4d8bff` on `#0a0a0a` → 5.4:1 (passes ≥ 3:1 adjacent-contrast) |
| Applied to | Every interactive element: buttons, links, the ThemeToggle, form controls (deferred). **No element is exempt.** |
| Rounded-corner handling | `outline-offset: 2px` ensures the ring reads clearly around any `border-radius` value; no need per-element override. |

**Binding rules for all phases:**
- `:focus-visible` (not `:focus`).
- Never `outline: none` without a replacement visible indicator of equal or greater contrast.
- The ring color is `--color-accent` in both themes — this is a reserved accent usage (see Color §Reserved-for list).

## Motion Contract

### Phase 1 motion policy

**There is no motion in the Phase 1 proof-of-life page.** No transitions, no animations, no hover effects. The only state change is the theme class flipping on `<html>`.

### Theme-flip transition handling

`next-themes` `ThemeProvider` is configured with **`disableTransitionOnChange={true}`** (RESEARCH Pattern 2). This injects an inline `* { transition: none !important }` during the one frame the class swap occurs, preventing the cascading color-transition flash that happens when many `transition-colors` elements flip simultaneously. **This prop is mandatory** — omitting it causes a visible ugly flash during theme toggle (RESEARCH §Common Pitfall 4).

### `prefers-reduced-motion` contract (binds all phases)

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

This global reset ships in `globals.css` in Phase 1 and covers every downstream phase by default. Any phase introducing animation (Phase 4 section reveals, Phase 5 card hovers) **must not** override this media query.

## Proof-of-Life Page Contract (`src/app/page.tsx`)

### Purpose

Prove the stack: Geist Sans loads, Geist Mono loads, tokens resolve, `.dark` class flips tokens, ThemeToggle works with no FOUC on hard refresh.

### Structure

```
<main> (semantic, the only landmark on the page)
  <header> (in-page, not the site header — that's Phase 3)
    <span class="mono, caption-size, text-secondary">PLACEHOLDER_SITE_TITLE</span>
    <ThemeToggle />
  </header>
  <h1 class="display-size, extrabold, tracking-tight, text-primary">PLACEHOLDER_NAME</h1>
  <p class="body-size, regular, text-secondary, max-w-prose">PLACEHOLDER_TAGLINE</p>
</main>
```

**No site-level header, nav, or footer.** Those are Phase 3 deliverables. A temporary in-page `<header>` element is acceptable here to provide a home for the `ThemeToggle` and the placeholder site title — its styling is throwaway.

### Copywriting sentinels

Every user-visible string in Phase 1 is a **placeholder sentinel** (CLAUDE.md mandate — `git grep PLACEHOLDER_` must locate every pre-launch edit):

| Element | Exact string | Will be replaced in |
|---------|-------------|---------------------|
| Header label (mono) | `PLACEHOLDER_SITE_TITLE` | Phase 2 (from `/data/site.ts`) |
| H1 (display) | `PLACEHOLDER_NAME` | Phase 4 (from `/data/site.ts` + hero section) |
| Subhead (body) | `PLACEHOLDER_TAGLINE` | Phase 4 (from `/data/about.ts` or `/data/site.ts`) |
| Document `<title>` (metadata export) | `PLACEHOLDER_SITE_TITLE` | Phase 6 |
| Document `<meta description>` | `PLACEHOLDER_SITE_DESCRIPTION` | Phase 6 |
| ThemeToggle `aria-label` | `Switch to light theme` / `Switch to dark theme` (dynamic by `resolvedTheme`) | Final (no placeholder — these are production strings) |

**Non-negotiable:** Executor must not invent real content for Phase 1. Real name, bio, tagline do not exist yet per PROJECT.md. Every visible string is a sentinel.

### Rendering model

- `src/app/page.tsx` is a **Server Component** (no `"use client"` directive) that imports `<ThemeToggle />`.
- `src/components/theme-toggle.tsx` is the **only** `"use client"` leaf component in Phase 1.
- `src/providers/theme-provider.tsx` is `"use client"` because `next-themes` requires it, but it's a thin wrapper consumed once from the root layout.

**Binding for all phases:** `app/page.tsx` and every `app/projects/[slug]/page.tsx` must remain Server Components. Page-level `"use client"` is forbidden (CLAUDE.md, RESEARCH §Pitfall 12).

### Layout & spacing on the proof-of-life page

- `<main>`: `min-h-screen` (the whole viewport), `px-6` (24px gutter mobile) / `md:px-16` (64px gutter desktop), `py-12` (48px vertical padding).
- In-page `<header>`: `flex items-center justify-between mb-12` (label left, toggle right, 48px below).
- `<h1>` and `<p>`: stacked, `mt-4` between them (16px).

No decorative elements, no background images, no hero graphics.

### ThemeToggle affordance (the only interactive element in Phase 1)

| Property | Value | Rationale |
|----------|-------|-----------|
| Element | `<button type="button">` — **must be a real `<button>`**, never a `<div>` or `<span>` with `onClick` | Keyboard accessibility, screen reader recognition (RESEARCH §Common Pitfall, PITFALLS.md §13) |
| Shape | Square clickable area, 44×44px minimum (`h-11 w-11`) | Touch-target minimum (A11Y-06) |
| Visible icon in Phase 1 | Unicode glyph: `☀` (sun, when in dark mode — "switch to light") / `☾` (moon, when in light mode — "switch to dark"). **Raw character, not an SVG, not an icon library.** | `lucide-react` is not installed in Phase 1; this is a temporary placeholder. Phase 3 replaces with lucide `Sun` / `Moon` icons and establishes the production affordance. |
| Icon visible size | ~18–20px (readable against 44px target) | Hit target ≥ 2× visible element gives comfortable touch |
| `aria-label` | Dynamic: `` `Switch to ${next} theme` `` where `next` is the theme that will be active after click. **Do not** swap an "Open menu" / "Close menu" style label — screen readers re-announce on every change and that creates noise. | RESEARCH §Common Pitfall 5, PITFALLS.md §13 |
| Keyboard behavior | Enter and Space toggle (default `<button>` behavior — do not override) | WCAG 2.1.1 |
| Focus-visible ring | Inherits from the global `:focus-visible` rule — 2px `--color-accent` outline with 2px offset | Matches the focus contract |
| Hydration guard | Renders a layout-preserving placeholder (`disabled`, same 44×44 footprint, no icon) until `mounted` is true. Prevents the `useTheme()`-returns-undefined hydration mismatch (RESEARCH §Common Pitfall 5). | |
| Background / border in idle state | None. Transparent. Shape defined by hit target, not a visible container. | Minimal aesthetic |
| Hover state | **None in Phase 1.** Phase 3 may add a subtle `bg-surface` hover when the toggle joins the real nav. | No motion in Phase 1 |

## Accessibility Contract

Every bullet below is binding for Phase 1 and carries into downstream phases unless a later UI-SPEC explicitly overrides.

### Semantic HTML
- Root element: `<html lang="en" suppressHydrationWarning className="{GeistSans.variable} {GeistMono.variable}">` — lang attribute non-negotiable.
- Page element: a single top-level `<main>` on `page.tsx`.
- No divs-with-onClick masquerading as buttons. No links-without-href.
- Heading order: `<h1>` exists exactly once on the proof-of-life page. No `<h2>` on this page.

### Keyboard navigation
- Every interactive element reachable via Tab.
- Focus-visible ring visible on every interactive element (contract above).
- No keyboard traps. On Phase 1 there is only one interactive element (ThemeToggle) so this is trivially satisfied.
- Tab order matches visual reading order (header-label, ThemeToggle, any in-body links — none in Phase 1).

### Contrast
- AAA for primary body text (≥ 7:1), AA for secondary (≥ 4.5:1), AA-interactive for accent (≥ 3:1). Six pairings — see Color §Contrast gate.
- Enforced at the token layer via the Vitest `tests/tokens.contrast.test.ts` suite. CI-gated.

### Reduced motion
- `@media (prefers-reduced-motion: reduce)` global reset shipped in `globals.css` (Motion §`prefers-reduced-motion`).
- Theme flip is instantaneous (`disableTransitionOnChange` — no transition involved at all, reduced-motion-compatible by construction).

### Screen reader considerations
- ThemeToggle `aria-label` is dynamic-but-stable (`Switch to dark theme` ↔ `Switch to light theme`, never "Open/Close") — see ThemeToggle affordance table.
- No `aria-hidden` on anything in Phase 1.
- `suppressHydrationWarning` is applied only on `<html>` (one level deep) — not on descendants.

### Responsive / mobile
- Viewport meta tag: inherited from `create-next-app@16` default (`width=device-width, initial-scale=1`). Verify it's in `app/layout.tsx`.
- 375px width: no horizontal scroll on the proof-of-life page.
- Touch targets: the ThemeToggle hit area is ≥ 44×44px (A11Y-06).

### What Phase 1 does NOT verify (deferred)
- Screen reader walkthrough (Phase 7 `@axe-core/playwright`).
- Lighthouse a11y score ≥ 95 (Phase 7 CI gate).
- Real keyboard tab-through of a multi-element page (Phase 7; Phase 1 has one interactive element).

## Anti-Patterns Explicitly Forbidden

These are forbidden across the whole project per CLAUDE.md, PROJECT.md, and RESEARCH §Anti-Patterns. Listing here so the executor can't hand-wave them and the UI checker can flag any violation.

### Visual / UX
- **Proficiency bars, percentages, "beginner / intermediate / expert" labels.** Anywhere, ever (not just Skills section).
- **"Ninja / rockstar / passionate / driven / creative / innovative" copy.** Even in PLACEHOLDER_* sentinels.
- **Typewriter hero effect.** Blocks content; fails 30-second recruiter scan.
- **Splash-gate / intro overlay before content paint.**
- **Tech-logo auto-marquee.** Signals dated.
- **Auto-playing audio or video.** Anywhere.
- **Hero videos or 3D backgrounds.** Content-weight, not decoration-weight.
- **Pure `#000` dark-mode background.** Use `#0a0a0a`.
- **Low-contrast "elegant" palettes** (< AA ratios). The Vitest contrast gate blocks this structurally.

### Technical
- **Hand-rolled hamburger / custom focus-trap logic.** Phase 3 must use Radix NavigationMenu or Headless UI. Phase 1 does not ship a hamburger but calling out so the planner/executor does not invent one "temporarily".
- **Page-level `"use client"`.** Any `app/**/page.tsx` or `app/**/layout.tsx` file with `"use client"` at the top is a hard reject. Only true leaf components get the directive.
- **`framer-motion`.** Use `motion` (the renamed package). Not installed in Phase 1; called out for Phase 4.
- **`react-icons`, `styled-components`, `emotion`, `Chakra`, `MUI`, `Mantine`.** All banned per CLAUDE.md.
- **Any global state library** (Redux, Zustand, Jotai, Valtio, Recoil). Not needed.
- **`tailwind.config.js` / `tailwind.config.ts` file.** Tailwind v4 uses CSS-first `@theme`; the config file is "scaffolding theatre" that misleads reviewers.
- **Google Fonts `<link>` tags or `next/font/google` Geist imports.** `geist` npm package only (CONTEXT D-01).
- **`useEffect`-based theme toggle.** Flashes. Use `next-themes`.
- **`suppressHydrationWarning` on elements other than `<html>`.** One level deep only.
- **`outline: none` on any interactive element** without an equivalent visible replacement.

## What Phase 1 Does NOT Design

Explicitly out-of-scope for this UI-SPEC so downstream phases do not consume stale or overreaching assumptions from it:

@import "tailwindcss";

@custom-variant dark (&:where(.dark, .dark *));

@theme {
  /* fonts — alias Geist's variables to Tailwind's font-sans / font-mono */
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);

  /* color tokens — light theme defaults */
  --color-background: #ffffff;
  --color-surface: #f7f7f7;
  --color-border: #e5e5e5;
  --color-text-primary: #0a0a0a;
  --color-text-secondary: #525252;
  --color-accent: #0057ff;

  /* type scale — major third (1.25) */
  --text-caption: 0.8125rem;
  --text-body: 1rem;
  --text-lg: 1.25rem;
  --text-h4: 1.5625rem;
  --text-h3: 1.953125rem;
  --text-h2: 2.44140625rem;
  --text-h1: 3.0517578125rem;
  --text-display: 3.814697265625rem;
  --text-mono-sm: 0.875rem;
  --text-mono-base: 1rem;

  /* weight tokens — rely on Tailwind defaults for 800 */
  --font-weight-regular: 400;

  --font-weight-bold: 700;

  /* radii */
  --radius-sm: 0.125rem;
  --radius-md: 0.25rem;
  --radius-lg: 0.5rem;
}

/* dark-theme overrides — declared AFTER @theme so cascade wins */
.dark {
  --color-background: #0a0a0a;
  --color-surface: #161616;
  --color-border: #262626;
  --color-text-primary: #fafafa;

@media (prefers-reduced-motion: reduce) {

    animation-duration: 0.01ms !important;

## Checker Sign-Off

- [ ] **Dimension 1 — Copywriting:** Every user-visible string is a `PLACEHOLDER_*` sentinel or a permanent aria-label. No real content, no "ninja/rockstar/passionate/driven/creative", no typewriter hero.
- [ ] **Dimension 2 — Visuals:** Proof-of-life page has a single `<main>`, an in-page header with the mono site-title label and ThemeToggle, an `<h1>` display heading, and a body paragraph. Zero decorative elements, zero anti-pattern visuals.
- [ ] **Dimension 3 — Color:** 60/30/10 monochrome split encoded, `--color-accent` reserved to the explicit reserved-for list, all six text/interactive contrast pairings pre-verified, dark-mode base is `#0a0a0a` (not `#000`).
- [ ] **Dimension 4 — Typography:** 10 type-scale tokens declared (caption, body, lg, h1–h4, display, mono-sm, mono-base), 3 explicit weight tokens + 1 inherited, Geist Sans for all prose/headings, Geist Mono scoped to code/tags/kbd/meta accents only.
- [ ] **Dimension 5 — Spacing:** 4px-base scale leveraging Tailwind v4 defaults, touch targets ≥ 44×44px, section/gutter/component padding disciplines documented.
- [ ] **Dimension 6 — Registry Safety:** No registry installs in Phase 1; `components.json` not created; safety gate not applicable.
